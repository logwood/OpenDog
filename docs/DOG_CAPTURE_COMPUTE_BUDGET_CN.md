# 狗脸采集：静态计算量与调用预算（2026-11-14）

在修改和回放之前，先从 ONNX 图、固定输入尺寸、调用依赖和已有分支记录计算预算。本次没有重新运行模型或视频；新增分析器只做形状推导与整数计数，使用第 12 节已经归档并验证一致的调用记录。

## 1. 计量口径

**1 MAC = 一次乘加，MMAC = 百万次乘加，GMAC = 十亿次乘加。** 本文统计 Conv、Gemm、MatMul 的逻辑稠密乘加；按常用约定，其点积 FLOPs 为 `2 × MACs`。这个数不包含偏置、激活、归约、插值、内存复制或线程调度。分析器逐项列出其他算子的数量和输出规模，避免将未纳入 MAC 的工作理解为没有开销。

卷积可以直接计算：

```text
MAC_conv = N × H_out × W_out × C_out × (C_in / groups) × K_h × K_w
MAC_matmul = 输出元素数 × 收缩维度 K
```

卷积权重形状已经是 `[C_out, C_in/groups, K_h, K_w]`，不能再除一次 `groups`。矩阵乘法须处理 batch 广播、向量和转置。定义对应 [ONNX Conv](https://onnx.ai/onnx/operators/onnx__Conv.html)、[MatMul](https://onnx.ai/onnx/operators/onnx__MatMul.html)、[Gemm](https://onnx.ai/onnx/operators/onnx__Gemm.html)。固定输入的中间形状由 [ONNX 形状推导](https://onnx.ai/onnx/repo-docs/ShapeInference.html) 得到；跟踪模型的 Shape/Gather/Slice 表达式进一步用 ORT 的符号形状推导求解，不执行网络。

这些是模型定义的逻辑工作量。CPU 的通道填充、算子融合、卷积算法和缓存复用会改变实际指令与物理访存。分析器记录的张量字节数是图的逻辑输出规模，不是 DRAM 流量或峰值内存；例如融合前的激活中间张量可能根本不会单独写出。

## 2. 三个已归档模型的固定成本

| 模型 | 输入 | 单次 MMAC | 点积 GFLOPs（2×MAC） |
|---|---|---:|---:|
| 脸部检测与姿态，完整头部 | 1×3×320×320 | **826.574** | 1.6531 |
| 关键点跟踪 | 1×3×128×128 | **71.665** | 0.1433 |
| YOLOX 身体检查 | 1×3×416×416 | **522.553** | 1.0451 |

完整大网一次是小跟踪网的 **11.53 倍**。因此把一次本可避免的大网调用消掉，通常比改写少量姿态数组有大得多的算术预算。身体网络本身也不便宜，其是否优先取决于触发次数；Wolfhound 只调用了 1 次，用户视频是 125 次，不能只看单次成本给两个视频相同排序。

各模型 SHA256 和逐算子汇总在 [static_compute_budget.json](../assets/dog_capture/static_compute_budget.json)。计算从原 portable checkpoint 出发，当前 CPU 条件图的执行成本通过原节点分组与实际分支记录得到；不把 CPU 融合节点当成普通卷积强行套公式。

## 3. 脸部大网内部的算力分布

| 原图中的互不重复部分 | MMAC | 占完整模型 |
|---|---:|---:|
| 共享网络与全部分数 | **601.370** | **72.755%** |
| 最细 40×40 尺度的框/关键点头 | 146.291 | 17.699% |
| 中间 20×20 尺度的框/关键点头 | 55.466 | 6.710% |
| 最粗 10×10 尺度的框/关键点头 | 23.313 | 2.820% |
| 非空输出的解码点积 | 0.134 | 0.016% |
| 合计 | **826.574** | 100% |

“共享网络与分数”包括它们的全部祖先，和三个独立头部不重复计算。解码行的 0.134 MMAC 只包含其点积卷积；Softmax、坐标变换等其他工作另列在 JSON，不能说全部解码只有这个成本。

令三个尺度是否存在通过原分数阈值的候选分别为 `I_f / I_m / I_c`：

```text
C_face = 601.3696
       + I_f × 146.2912
       + I_m ×  55.4656
       + I_c ×  23.3128
       + I_any × 0.1344       # 单位 MMAC
```

| 分支情况 | 每次脸部网络 MMAC |
|---|---:|
| 无候选，已有整图短路 | 601.370 |
| 仅最粗尺度 | 624.817 |
| **仅中尺度，当前视频常见路径** | **656.970** |
| 中＋粗尺度 | 680.282 |
| 仅最细尺度 | 747.795 |
| 三个尺度全部运行 | 826.574 |

这给出两条无需回放就能得到的边界：

- 保持共享网络不变，即使原模型所有头部点积都免费，完整模型的 MAC 最多减少 **27.25%**。
- 上一轮优化后的常见中尺度路径，**91.54%** 的 MAC 已在共享网络与分数中；继续优化它剩余的头部/解码点积，最多影响 **8.46%**。这仍是算术量的边界，不是延迟保证。

因此，继续围绕输出数组和头部的小改动，收益空间已经可量化。更大的候选需要涉及共享网络本身，或者证明某次共享网络执行可以取消。

## 4. 把单次成本放回调用链

下面以一个跟踪对象、每次大网只激活中尺度为例。不同裁剪仍是不同网络输入，不能因使用同一模型就假定共享骨干结果可以复用。

| 路径 | 小网次数 | 大网次数 | 网络合计 GMAC |
|---|---:|---:|---:|
| 普通跟踪 | 1 | 0 | **0.0717** |
| 全图检测＋跟踪 | 1 | 1 | 0.7286 |
| 跟踪＋精定位＋复检＋镜像 | 1 | 3 | 2.0426 |
| 再叠加全图检测和一次倾角修正 | 1 | 5 | **3.3565** |

最后一行是普通跟踪网络工作的 **46.84 倍**。此前归档的 Wolfhound **第 232 帧恰好是这个情况**：全图检测 1 次、精定位 2 次、复检 1 次、镜像 1 次，全部是中尺度，跟踪网 1 次。此处由已有调用事件和分支位计算，没有拿 56 ms 反推算力。

若同样 5 次大网全部激活三个头，则是 **4.2045 GMAC**。这是一条指定单犬路径的成本，不是所有配置下的单帧上界；其他帧还可能有身体检查、多犬、重新搜索等分支。

原来的结构依赖是：第一次精定位 → 必要时修正倾角 → 得到新几何 → 复检 → 通过后镜像。可以分别预算总工作量和串行路径。将工作并行或改到其他线程，可能改变响应延迟，但 MAC 总量不会因此减少。

## 5. 直接复用已有分支统计计算整段预算

无需重新跑视频，读取第 12 节保存的调用数、各尺度激活直方图即可求和。对每个调用入口单独使用其分布，避免把候选镜像与全图检测错误地假设成同一概率。

| 视频 | 上轮优化前全部网络 GMAC | 分尺度优化后 GMAC | 网络 MAC 减少 | 优化后平均 MMAC / 输入帧 |
|---|---:|---:|---:|---:|
| 用户视频 | 561.406 | **535.547** | 4.61% | 407.570 |
| Wolfhound | 325.060 | **277.705** | 14.57% | 229.129 |

这里包括脸、身体和小跟踪网，比较的是上一轮整图条件图与分尺度条件图。各调用入口优化后的累计预算：

| 入口 | 用户视频 GMAC | Wolfhound GMAC |
|---|---:|---:|
| 全图/ROI 等其他脸部调用 | 330.343 | 100.369 |
| 候选精定位，包含倾角重试 | 23.824 | 47.070 |
| 复检，不含镜像 | 30.334 | 22.328 |
| 镜像 | 1.305 | 19.052 |
| 小跟踪网络 | 84.421 | 88.363 |
| 身体网络 | 65.319 | 0.523 |

Wolfhound 的平均网络预算比用户视频小，但候选验证集中在少数帧，解释了它平均耗时较短、慢帧更重的结构来源。新视频的分支次数尚未知时，应给每条路径的固定成本与分支组合范围；已有完整记录时可以直接加权，不必再测同一段视频。

## 6. 图像与控制处理用像素和字节另外记账

这些位置同样能预算，但用 MAC 一个数不足以表达它们的资源需求。

| 位置 | 可直接计算的工作规模 |
|---|---|
| 320×320 BGR → FP32 网络输入 | 307,200 个通道元素；输入/输出有效载荷合计 **1.536 MB**；归一化使用 307,200 次标量乘法 |
| 128×128 跟踪输入打包 | 49,152 个通道元素；输入/输出有效载荷合计 **0.246 MB** |
| 320×320 三通道双线性仿射 | 最多 **1,228,800** 个加权采样贡献，加坐标、边界与舍入处理 |
| 128×128 三通道双线性仿射 | 最多 **196,608** 个加权采样贡献 |
| 大幅面积下采样 | 同时依赖源 ROI 与目标大小；已有 Wolfhound 示例是 **1280×720×3 → 128×72×3**，源张量 2.765 MB |
| 质量检查 | 固定 224×224 画布，基础灰度网格 **50,176** 个位置，随后掩码统计、滤波和眼睛区域处理 |
| 姿态/关联/选图 | 少量关键点、轨迹与候选的数量；当前各角度 `top_k=1` |
| NMS | 通过分数阈值的候选数 K；排序与框之间的比较工作依赖 K，不能每帧直接按全部 2,100 个位置的平方计费 |

表中的 MB 为十进制，张量有效载荷不包括中间复制或缓存流量。双线性采样贡献也不等同于 CPU 浮点 MAC 指令数：具体内核可能用定点、查表和 SIMD。面积缩放的整数比例快速路径与一般面积权重路径不同，分析应按实际尺寸选择其算法计数；实现依据见 [OpenCV resize 源码](https://raw.githubusercontent.com/opencv/opencv/5.x/modules/imgproc/src/resize.cpp)。

这解释了为什么“大图缩小”可能比操作小数组贵：它处理的是源像素、权重、访问与缓存，不是只对目标 128×128 执行一次操作。采样精度约束仍然保留，不能把删除抗锯齿等同于等价的减算。

## 7. 用预算决定什么值得实现

后续先为候选改动填写三个量：**减少多少 MAC、减少多少数据访问、缩短哪条串行路径**，再附上覆盖次数、实现代价和精度影响。简单例子：

- 每取消一次常见中尺度大网，节约 **656.97 MMAC**，约为 **9.17 次**小网。这使“可证明的提前拒绝”和重复执行消除值得优先检查；已有审计中相同输入重复为零，不能虚构缓存收益。
- 取消已采集角度的改善窗口，预算为窗口内实际可删除调用的成本之和。它改变选图策略，应单独核对选中照片质量，不能借用之前逐帧一致性的结论。
- 合并 ONNX 图若没有取消节点或共享相同输入的中间结果，其逻辑 MAC 不变；收益应记在调度和数据搬运账上。
- 用约 71.66 MMAC 级别的小网络替代一次 656.97 MMAC 的验证，算术潜力约 **89.1%**；但现有跟踪网不能据此直接当作同等精度的验证器，训练与误接收验证属于该方案的实际成本。
- 当前中尺度输出头剩余预算只有约 8.46%，收益上限小的方案可以在编码前排除。

需要毫秒估计时，可按算子类型和尺寸，用已有计时校准有效计算吞吐、数据搬运和调度开销，并沿依赖路径求和。比如单个算子采用 `T ≈ max(点积工作/有效吞吐, 物理数据流量/有效带宽) + 调度开销` 的近似，再以已有数据给出范围；MAC 减少比例不直接等于整帧延迟减少比例。最终测试用于确认入围方案的数值/选图一致性和真实尾延迟，而不是每出现一个想法都重跑两段视频。

## 8. 可复现入口与验收

```bash
python src/Pet-ReID-IMAG/tools/analyze_dog_capture_compute.py --face ORIGINAL_POSE.onnx --landmarks LANDMARKS.onnx --body YOLOX_NANO.onnx --audit assets/dog_capture/candidate_optimization_benchmark.json --output compute.json --nodes-output nodes.json
```

`--audit` 可省略；模型结构与路径示例仍可计算。`--nodes-output` 保存完整逐节点的名称、算子、输出形状、逻辑字节数和 MAC；脸部节点另标记所属执行分组。本机完整账本在 `artifacts/runs/dog_capture/static_compute_20261114/nodes.json`，摘要与第 232 帧证据在 `summary.json`。

分析器遇到未知算子、未解析形状、CPU 融合图或不支持的条件图会明确报错，不把它们记成零；条件分组限定到已归档 pose checkpoint。**14 项算术检查通过**，覆盖分组/深度卷积、Gemm 转置、MatMul 广播/向量、未知形状、错误收缩维度、条件分支和不支持算子。本次仅增加分析工具、证据和文档，生产采集实现未改动，因此没有重复运行实时视频基准。
