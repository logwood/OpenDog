# TensorRT v0.3 验证记录（2026-11-11）

TensorRT FP16、CUDA Graph 和连续空间 Softmax 已接入独立视频入口。用户视频完整分析由原 WebGPU 路径的 **133.5 fps 提升到 268.9 fps**；逐帧计算 P95 从 **26.19 ms 降到 8.81 ms**。默认显卡电源策略下，真实 30 fps 回放的 P95 为 **31.21–33.87 ms**，尚未达到 16.7 ms 的优化目标。离线吞吐与实时延迟分开记录。

## 环境与计时范围

- Windows、i9-13980HX、RTX 4060 Laptop 8 GB，驱动 566.07；未修改系统电源计划或显卡全局设置。
- Python 3.12.13、TensorRT 10.7.0.post1（CUDA 12）、CUDA Python 12.6.2.post1、NumPy 2.5.4、OpenCV 5.0.0.93。
- CPU 使用 LiteRT/XNNPACK 4 线程；原 GPU 路径为 WebGPU 脸定位与关键点，加 CPU 狗检测。
- 所有推理任务串行执行，固定 batch=1。CPU/WebGPU 基线在同一会话测量并复用于最终表，来源保存在 `baseline_origin.json`。
- 单模型耗时包含输入拷贝、推理和输出回传，等待 GPU 完成后结束计时；排除输入缩放与模型启动。离线 FPS 包含解码、选帧与 JSONL 写入，关闭预览编码。
- 实时延迟从**已解码帧提交**到结果可用，包含排队和计算，排除摄像头传感器、解码和显示。记录替换帧与源跳帧，不假定所有输入帧都经过推理。

## 单模型（中位数 / P95，ms）

| 模型 | CPU | 原 GPU 路径 | TensorRT 直接入队 | TensorRT + CUDA Graph |
|---|---:|---:|---:|---:|
| 脸定位 | 12.34 / 13.71 | 2.16 / 2.49 | 1.73 / 2.78 | **0.86 / 0.89** |
| 46 点与熵 | 60.71 / 63.77 | 4.84 / 5.41 | 2.07 / 2.85 | **1.49 / 1.54** |
| 狗检测与 NMS | 14.79 / 18.63 | 17.48 / 25.64 | 3.27 / 4.31 | **1.59 / 1.74** |

脸模型使用 4 个固定真实裁剪、零图、灰图各重复 8 次（每项 48 次）；检测使用 6 段自然视频各 3 帧、重复 8 次（144 次）。原 GPU 路径的检测仍是同一个 CPU 模型，不同测量时段会有波动。

直接转换的 TensorRT 关键点模型中，跨通道步进的 Softmax 经逐层测量耗时约 10.31 ms。改为保持每个关键点空间平面连续后，该层约 0.05 ms；整体关键点推理由约 11.49 ms 降至最终 1.49 ms。这里只改等价的计算布局，保留训练权重、原有取整坐标网格和 FP32 归约；没有调松选帧阈值。

## 完整视频与昂贵帧

| 输入 / 后端 | 离线 fps | 所有帧计算 P95 | 神经网络帧计算 P95 | 选中帧 |
|---|---:|---:|---:|---|
| 用户 / CPU | 54.0 | 92.55 ms | 405.90 ms | 正 271、左 282 |
| 用户 / 原 GPU | 133.5 | 26.19 ms | 68.69 ms | 正 271、左 282 |
| 用户 / TensorRT | **268.9** | **8.81 ms** | **21.38 ms** | 正 271、左 282 |
| Wolfhound / TensorRT | 126.1 | 15.65 ms | 22.35 ms | 正 192、右 146、左 398 |

“神经网络帧”包含有效与拒绝的神经推理帧；重新捕获可能尝试多个整 90°方向，因此一帧可能执行多次关键点推理。用户视频中很多帧被拒绝，只报告全帧 P95 会掩盖这部分成本。初步探针得到过 288.7 fps，正式对照以表内 268.9 fps 为准。

两次用户视频实时回放均保留正面 271、左侧 282；Wolfhound 回放保留正面 192、右侧 146、左侧 398。没有为了计时省略候选复核或质量检查。实时峰值 RSS 约 636–670 MiB；三个引擎合计 51,783,228 字节（约 49.4 MiB）。

进一步诊断发现低负载时显卡会进入 210 MHz / P8；单模型连续调用约 1–2 ms，间歇调用可达十几毫秒。GPU 事件计时也显示延迟发生在设备执行区间。加密检测频率、混用 WebGPU、提高本进程 QoS 的试验未达到目标，未作为默认实现。应用级“最高性能”配置的写入被驱动以 `NVAPI_ACCESS_DENIED (-175)` 拒绝，确认未留下配置；可选配置工具已经提供，开启后的效果尚未测量。不能把连续测速结果当作当前默认策略下的实时保证。

## 结果与数值核对

6 段自然视频共 4,194 帧，4 个构造用例共 389 帧，全部使用同一组默认门槛。

| 视频 | 帧数 | 正面 / 左 / 右 |
|---|---:|---|
| 用户视频 | 1314 | 271 / 282 / 缺失 |
| Wolfhound | 1212 | 192 / 398 / 146 |
| Labrador | 201 | 79 / 缺失 / 缺失 |
| Lurcher | 390 | 148 / 缺失 / 缺失 |
| Shepherd | 743 | 全部拒绝 |
| Whimpering | 334 | 全部拒绝 |
| 构造的有序转头 | 173 | 15 / 45 / 125 |
| 冻结正面 | 72 | 1 / 缺失 / 缺失 |
| 模糊正面 / 空白 | 各 72 | 全部拒绝 |

- 74 个既有粗标注检查点：22 个方向正确、26 个弃判、26 个正确拒绝，方向误判与错误质量放行均为 0。弃判不计为正确；这不是独立犬种准确率评测。
- 4 个真实脸裁剪上，TensorRT 对 CPU 的关键点最大归一化坐标差约 0.00225（384 像素输入约 0.86 像素），熵最大差约 0.01094。全 6 输入最大坐标差约 0.00311，最大熵差约 0.08529，后者出现在非脸的灰图。
- 18 个检测输入上的狗数量全部一致；匹配狗框最小 IoU 约 0.902，置信度最大差约 0.02344。检测导出移除了激活量化，不能宣称逐位一致。
- 连续布局改写同时对照原 ONNX 头与独立 FP64 计算，测试包括均匀、普通、极尖锐热图；原来的取整坐标网格保持不变。
- 52 项测试通过，包含实际 TensorRT 引擎、CUDA Graph 与直接入队一致性、跨工作线程调用、NMS、时序/身份重置、原帧复核、零模型上游输入等。
- 23 份完整运行结果中的 41 张选中整帧及裁剪均与归档源视频像素严格一致。用户输入视频 SHA-256 保持 `6db00b4f53f1ac995df48bdd96a3f32879717dfa52af9d1ef793550c827ebc06`。
- 人工复看最终选图：用户正面与左侧以及 Wolfhound 三个方向符合目标；Lurcher 的清晰帧仍存在眯眼/闭眼，本模块没有独立的睁眼分类器。未把它表述为人脸 eKYC 级活体认证。

## 交付与复现

完整结果保存在 `artifacts/runs/dog_capture/v3_final`，包含逐帧日志、原图、网页、微基准、完整视频对照、实时回放、引擎元数据和像素校验。初始直转引擎、布局探针和失败的性能试验单独保留，未混入正式性能表。

本地交付包 `delivery/dog_view_selection_v3_trt.zip` 包含源码、原始视频、模型、ONNX、引擎与结果。TensorRT/TensorFlow 安装包不打入交付，首次通过固定版本安装脚本获取。Git 保存代码、资产清单、配置和紧凑结果摘要；用户私有视频与大模型留在本地。安装、输入接口和命令见 [DOG_TENSORRT_CN.md](DOG_TENSORRT_CN.md)。

本轮完成桌面 TensorRT 后端与验证；CPU 独立三模型实时性能、手机真机耗时及跨犬种泛化，不通过 GPU 微基准外推。已有五点模型的系统可继续走不追加模型的选帧接口，v2 的接口与验证结果保持兼容。
