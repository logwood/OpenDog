# 指定位置选帧 v0.2 验证记录

2026-11-10，Windows，i9-13980HX、RTX 4060 Laptop 8 GB。桌面解释器为 Python 3.12.13，NumPy 2.5.4、OpenCV 5.0.0.93、LiteRT 2.3.0。OpenCV 单线程，CPU 模型 4 线程。核心结果目录为 `artifacts/runs/dog_capture/v2_release`，交付包内对应 `results`。

## 先看满足了什么

- 新的 `TargetViewPipeline` 接收现有 AnyFace 五点和脸框，不加载额外模型；原始视频入口仍可独立运行。
- 默认正面、左侧、右侧各一张，任意顺序收集，姿态确认与清晰候选分开。原版动作序列没有被当作选图的前置要求。
- 实际输出图片保留原像素，逐帧原图和裁剪均做了源视频像素一致性校验。
- 已通过 46 项测试、6 段自然视频和 4 个构造用例；完成真实 AnyFace 输出接入、整段实时窗口回放及输出压缩的交替对照。

## 现有模型复用：新增成本

使用仓库原有 AnyFace YOLOv5l6、800 输入。先实际计算其输出，再由隔离的选帧环境回放这些结果；五点选择模块的模型调用计数为空。下面的毫秒数仅是**新增选帧计算**，不包含上游检测。

| 素材 | 处理的上游观测 | 新增计算 P50 / P95 | 输出 |
| --- | ---: | ---: | --- |
| 用户视频 | 657 | 0.05 / 0.53 ms | 正面第 266 帧，8.867 秒 |
| Wolfhound 自然视频 | 606 | 1.53 / 3.04 ms | 正面 184、左侧 286、右侧 158 |

用户视频大部分帧被上游检测或几何检查拒绝，因此其总体耗时分位数较低；不能拿 0.53 ms 当作每张有效狗脸的固定处理耗时。Wolfhound 的 606 个输入均有单脸检测，更能反映持续工作时的新增成本。

上游 AnyFace 的实际推理 P50/P95：用户视频 18.50/21.91 ms，Wolfhound 19.23/22.08 ms；如果业务原本没有运行它，这笔成本必须另外计算。采样请求 15 fps，用户视频实际每两帧取一次，Wolfhound 的 24 fps 源实际每两帧取一次，即 12 fps。这里证明的是接入与增量开销，不是完整应用在缓存模式下免费达到高帧率。

五点转正只做几何计算。用户视频中存在明显画面旋转；加入转正与位置退出迟滞后，保留了夹在短暂模糊之间的第 266 帧，仍未强行补出左右图。两套关键点的鼻部定义不同，输出帧可不同；没有把不同入口的图片拼成一次三位置通过。

## 独立原始视频入口

同一套默认参数，逐帧分析、无预览编码，未加载任何 Re-ID/SAM 模型。

| 自然视频 | 帧数 | 分析 fps | 计算 P95 | 最终位置及帧号 |
| --- | ---: | ---: | ---: | --- |
| 用户视频 | 1314 | 122.2 | 31.1 ms | 正面 271、左侧 282；右侧缺失 |
| Wolfhound | 1212 | 89.2 | 28.8 ms | 正面 192、左侧 399、右侧 146 |
| Labrador barking | 201 | 89.5 | 31.7 ms | 正面 38 |
| Lurcher lick | 390 | 109.3 | 32.3 ms | 正面 304 |
| Shepherd apple | 743 | 98.5 | 30.8 ms | 没有合格图 |
| Dog whimpering | 334 | 72.3 | 29.8 ms | 没有合格图 |

共 4194 帧。速度包含解码、选帧与逐帧 JSONL 写入，排除模型初始化和最终 PNG 写出，不是每帧都做一次神经网络推理；跟踪与刷新模式在 JSONL 中逐帧可见。

原有 74 个粗标注检查点中，48 个方向点：19 正确、29 弃判、0 错方向；26 个负样本点全部拒绝。范围更窄且独立确认更严格，弃判单独计数，不当作识别正确。标签在开发中使用过，不是独立犬种测试集，不能据此宣称 100% 准确。选中的 Lurcher 图存在眯眼；当前局部清晰度评分不等价于可靠的睁眼/无遮挡分类器。

## 实时回放

完整播放用户视频，30 fps，实际打开窗口，容量为 1 的待处理队列：

- 源视频 1314 帧，实际处理 1292 帧；解码调度跳过 14 帧、等待队列替换 8 帧，共 22 帧（1.67%）未分析。
- 实际处理 29.47 fps；采集提交到结果 P95 38.64 ms，队列等待 P95 5.91 ms，峰值进程 RSS 477.5 MiB。
- 选出正面 271、左侧 282，与逐帧入口一致。

计时起点为解码帧提交推理队列，不含摄像头曝光/驱动延迟。这里是文件按原帧率回放；没有将其写成物理摄像头或手机实测。

## 输出压缩的 A/B 对照

压缩图保持 46 点预测和全部预训练权重，仅把热力图熵在图内计算后输出。输出字节从 6,783,344 降到 552，模型文件约 11.55 MB，体积没有相同比例缩小。

6 个输入（4 个真实脸部裁剪、全黑、灰色），每个执行 5 次、交替调用先后顺序。测量包括推理、读回、置信度计算，排除加载和缩放。

| GPU 关键点模块 | P50 | P95 |
| --- | ---: | ---: |
| 完整热力图输出 | 23.26 ms | 33.22 ms |
| 图内熵归约 | 6.17 ms | 9.75 ms |

GPU 坐标最大绝对差为 0；6 个输入的熵摘要最大偏差小于 0.01。CPU 一致性测试验证坐标不变，熵偏差小于 0.014。熵不是校准过的可见性概率。

相同视频、相同最终选帧逻辑、无预览编码，采用 A-B-B-A 顺序：

| 运行 | 分析 fps | 计算 P95 | 输出 |
| --- | ---: | ---: | --- |
| 完整输出 A1 | 101.36 | 36.27 ms | 正面 271、左侧 282 |
| 压缩输出 B1 | 146.91 | 23.48 ms | 正面 271、左侧 282 |
| 压缩输出 B2 | 140.91 | 23.26 ms | 正面 271、左侧 282 |
| 完整输出 A2 | 99.05 | 38.93 ms | 正面 271、左侧 282 |

该次对照平均吞吐约 100→144 fps；较早的同机工程测量约 120→150 fps，机器负载与功耗状态会影响绝对数值。两次对照均保留相同最终帧，不把传输字节的缩减比例当作整套应用的加速比例。
