# Pet-ReID-IMAG 复现后改进账本

## 1. 账本目的

这份账本把“忠实复现”和“方法改进”分开管理。发现可疑设计时先记录证据，不直接改进复现基线；完成可量化基线后，再以一次只改变一个因素的方式做消融。

状态约定：

- `基线冻结`：为了可比性，复现完成前不改。
- `已确认疑点`：代码行为已经核实，但尚不能断定作者意图。
- `必要偏离`：受 8GB 显存或现代环境约束，已经有记录地偏离作者设置。
- `待实验`：复现成功后可以开始对照实验。
- `接受` / `拒绝`：实验完成后按预先定义的指标决策。

## 2. 基线层级与改进门槛

| 层级 | 定义 | 当前状态 |
|---|---|---|
| G1 功能复现 | 数据、训练、验证、恢复、推理、融合全链路可运行 | 已完成 |
| G2 单模型定量复现 | `s101_224` 在身份不相交验证集完成 35 epoch，保存完整 AUC 曲线和最佳 checkpoint | 未完成 |
| G3 四分支复现 | 四个分支完成同一验证协议，随后用全部 6,000 ID 重训并生成融合结果 | 未完成 |

在 G2 前，不把下表中的方法改进合入 `modern_*.yaml` 基线。G2 后可以开展单模型消融；涉及融合或蒸馏的改进等 G3 后再比较。

## 4. 模型结构创新主线（复现后第一优先级）

核心方向不是继续堆四个近似模型，而是针对宠物身份信息的来源设计一个结构：头脸形态、全身轮廓、毛色纹理和局部稳定标记在姿态、遮挡和背景变化下应当被分别建模，再由视角条件自适应融合。

### A-01 首选方案：视角条件的全局—局部多尺度网络

建议把第一版创新模型定义为一个共享 backbone、多个轻量身份分支：

```text
整张图像
  → 共享多尺度 backbone
      ├─ Global branch：全身轮廓与整体毛色
      ├─ Head/face branch：头脸形态、耳朵、眼周和口鼻
      ├─ Texture-token branch：自动选择稳定毛纹/斑点区域
      └─ View gate：根据正面、侧面、背面、局部图和遮挡程度动态加权
  → 融合投影
  → 单个身份描述符
```

第一版不要求昂贵的人工部件标注：可以用可学习 part queries 从 feature map 中抽取 K 个局部 token，并用 token 多样性约束防止所有 token 聚集到同一区域。后续再比较显式头部检测或姿态关键点对齐。

| ID | 优先级 | 结构创新 | 为什么适合宠物 ReID | 第一个可验证版本 | 状态 |
|---|---:|---|---|---|---|
| A-01 | P0 | 全局 + 可学习局部 part tokens | 同一只狗在不同照片中姿态差异很大，但头脸和局部毛纹可能分别保持稳定。 | 在 S101 feature map 上增加 4 个 part queries；global/part descriptor 联合训练。 | G2 后首选 |
| A-02 | P0 | 视角/可见性条件门控 | 正面照应偏重头脸，侧面/背面照应偏重轮廓和毛纹；固定等权融合不合理。 | 轻量 gate 输出各分支权重，并报告不同视角下的权重分布。 | A-01 后 |
| A-03 | P1 | 单模型多尺度特征金字塔 | 当前 224/256/288 三模型重复计算；不同尺度信息可以在共享 backbone 内产生。 | 融合 stage 3/4/5 特征，各自池化后投影，替代三个 S101。 | 待实验 |
| A-04 | P1 | 前景—背景解耦双流 | 整图模型可能记住草地、室内或拍摄者环境，而不是狗的身份。 | 原图流 + 前景 mask 流，共享部分权重；加入背景扰动一致性。 | 待实验 |
| A-05 | P1 | 全局检索 + 局部 token 重匹配 | 全局余弦可能漏掉小面积身份标记；局部对应适合处理遮挡和姿态变化。 | 先用全局 embedding 召回，再对候选 pair 做 token-to-token matching。 | 待实验 |
| A-06 | P2 | 多专家蒸馏到单模型 | 四模型融合有效但部署成本高；可把多尺度/深度互补知识压入一个结构。 | 四分支作 teacher，A-01/A-03 单模型作 student。 | G3 后 |

结构创新必须同时报告参数量、FLOPs、显存和推理延迟。若只是增加大量计算获得小幅 AUC，不视为成功；优先目标是一个模型接近或超过四模型融合。

### A-07 已实现候选：跨阶段持久 latent workspace

当前第一版不再把注意力当作末端插件，而是在正常 CNN 流之外维护一个跨 C2→C5 的隐式工作区：C2 下采样只读，C3/C4/C5 通过同一个共享 Read–Mix–Write 单元反复更新 8 个持久槽并门控写回视觉流。它保留原 GeM/BN 2048 维描述符和 CE/Triplet/Circle 损失，不加入辅助多样性或一致性损失。

| 项目 | 冻结值 / 验收结果 |
|---|---|
| latent | 8 slots × 192 dim，8 heads，MLP ratio 4，共享 recurrent cell，四个 stage embedding |
| 写回 | C3/C4/C5 残差写回；`g=0.05+0.95·sigmoid(a)`，初值 0.10，不能零门控死亡 |
| 冻结与学习率 | 顶层 `workspace` 从 step 0 训练；与 heads 相同基础 LR；只冻结 `backbone` |
| 监督 | 沿用 CE/Triplet/Circle；v1 不加 latent 辅助损失 |
| 健康监控 | gate、write ratio、grad norm、非零/有限梯度比例、slot variance/cosine，每 200 iter |
| 工程验收 | 单元测试 5/5；真实 AMP train/eval/checkpoint 通过；workspace 参数梯度覆盖率 100% |
| batch-28 资源 | 48.42M 参数；4,215 MiB；0.369s/iter；相对 baseline +379 MiB / +11.5% 时间 |
| 状态 | 实现完成 / 待完整 35-epoch 未见身份 AUC 对照，尚不宣称效果提升 |

dim 256 原型的同机结果为约 4,335 MiB、+17.3% step 时间，超过预设 15% 时间预算，因此按实现前约定回退到 dim 192；槽数、头数、四阶段交互和监督均未削减。详细数据流和命令见 `LATENT_WORKSPACE_DESIGN_CN.md`。

## 7. 推荐实验顺序

1. 完成 G2：不再改当前 S101-224 基线，得到可信 AUC 曲线。
2. 做 R-01（裁剪参数）和 R-02（224/244 推理尺寸），先消除作者代码疑点，得到干净强基线。
3. 对已实现 A-07 做与 S101-224 完全同协议的 35-epoch 对照；先用健康指标排除 latent/gate 死亡，再按未见身份 AUC 决策。
4. 若 A-07 有增益，再比较 A-01 的显式 part tokens，判断隐式工作区与显式局部建模是否互补。
5. 在有效结构上增加 A-02 视角门控，再做 global-only、latent/part-only、固定融合和动态融合消融。
6. M-02、M-05、M-08 等训练项只用于保证结构比较公平，不抢占结构主线。
7. 完成 G3 后做 A-06 蒸馏，最终目标是单模型接近或超过四模型融合。
